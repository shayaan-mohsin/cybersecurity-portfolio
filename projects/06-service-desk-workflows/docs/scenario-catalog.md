# Scenario catalog

All ten playbooks are synthetic designs. Eight form the proposed core; two are extensions. These are plausible support examples, not a measured ranking of ticket frequency.

| Scenario | Type | Focus | Scope |
| --- | --- | --- | --- |
| [LAB-INC-001 : Account locked before a scheduled meeting](../tickets/01-account-lockout.md) | Incident | P3 | Core |
| [LAB-INC-002 : Outlook desktop keeps asking for sign-in](../tickets/02-outlook-sign-in.md) | Incident | P4 | Core |
| [LAB-INC-003 : VPN connects but a team application will not open](../tickets/03-vpn-dns.md) | Incident | P4 | Core |
| [LAB-INC-004 : A stalled print job returns after an apparent recovery](../tickets/04-printer-reopen.md) | Incident | P4 | Core |
| [LAB-REQ-001 : Request for an approved PDF application](../tickets/05-approved-software.md) | Catalog request | Fulfillment due date | Core |
| [LAB-REQ-002 : Read-only access to a team file share](../tickets/06-file-share-access.md) | Catalog request | Fulfillment due date | Core |
| [LAB-REQ-003 : New starter account and device coordination](../tickets/07-new-starter.md) | Catalog request | Approved start-date commitment | Core |
| [LAB-INC-005 : User reports a suspicious sign-in email](../tickets/08-phishing-report.md) | Support incident / security handoff | P3 under support matrix; immediate security escalation | Core |
| [LAB-INC-006 : Multiple callers report a critical application outage](../tickets/09-multi-user-outage.md) | Incident / outage coordination | P1 | Extension |
| [LAB-REQ-004 : MFA access recovery after a phone replacement](../tickets/10-mfa-recovery.md) | Catalog request / restricted identity recovery | Identity recovery routing; reassess service impact | Extension |

The core demonstrates account support, application triage, connectivity, peripherals, catalog approvals, scoped access, onboarding coordination, user communication and a security handoff. Imaging and deployment appear in the researched roles, but actual imaging is outside the first version and must not be claimed from the onboarding playbook.
