# Cloud Log Investigation Playbook

## Purpose

This playbook gives a repeatable workflow for investigating AWS CloudTrail events in a small lab environment.

## Investigation Workflow

1. Define the time window.
2. Identify the actor.
3. Identify the event source and event name.
4. Determine whether the action succeeded or failed.
5. Review request parameters for exposure, privilege, persistence, or visibility risk.
6. Look for related events before and after the action.
7. Decide whether the event is expected, suspicious, misconfigured, or remediated.
8. Document the conclusion and recommended next step.

## Severity Model

| Severity | Meaning | Example |
|---|---|---|
| Critical | Could remove visibility, expose sensitive data, or create broad compromise risk | `StopLogging`, public admin port exposure, root use with risky action |
| High | Security-relevant change requiring prompt review | administrator policy attached, access key created, public S3 control removed |
| Medium | Needs validation or monitoring | denied action, failed sign-in, GuardDuty sample finding |
| Low | Routine activity or context event | stack update, tagging, read-only review |

Severity is an analyst triage label. It is not proof that an incident occurred.

## Investigation Scenarios

### Root Console Login

Questions:

- Was root use expected?
- Was MFA enabled?
- Was the source IP expected?
- Did root perform follow-up changes?

Recommended response:

- avoid routine root use
- confirm MFA
- review events after the login
- document why root was used

### Failed Console Login

Questions:

- Which identity was targeted?
- Was the source IP familiar?
- Was this a single failure or repeated activity?
- Was there a successful login after the failure?

Recommended response:

- check identity activity
- validate MFA
- look for password reset or access-key activity
- monitor repeated attempts

### IAM Policy Attachment

Questions:

- Which user, role, or group received the policy?
- Is the policy administrative?
- Was the change approved?
- Was it later removed?

Recommended response:

- validate business need
- remove broad permissions when unnecessary
- replace with least-privilege policy
- review related actions by the modified identity

### Access Key Creation

Questions:

- Who created the key?
- Which user owns the key?
- Is the key needed?
- Is there evidence of immediate use?

Recommended response:

- delete unused keys
- rotate keys when needed
- prefer temporary credentials
- monitor access-key usage

### Public Security Group Ingress

Questions:

- Which port was opened?
- Was the CIDR `0.0.0.0/0` or `::/0`?
- Is there an attached compute resource?
- Was the rule revoked?

Recommended response:

- revoke public admin access
- restrict to known source ranges
- prefer Systems Manager Session Manager over direct SSH or RDP
- alert on public admin ports

### S3 Public Access Change

Questions:

- Was Block Public Access changed?
- Was a public bucket policy attempted?
- Did the request succeed or fail?
- Does Access Analyzer show external access?

Recommended response:

- keep Block Public Access enabled
- remove public policies
- use least-privilege resource policies
- review bucket access with Access Analyzer

### CloudTrail Logging Change

Questions:

- Did someone stop, delete, or change logging?
- Did the action succeed?
- Was there an approved change window?
- Is there another logging source?

Recommended response:

- restore logging immediately if disabled
- alert on logging configuration changes
- restrict CloudTrail administration
- review surrounding activity

## Analyst Deliverable Template

Use this structure for a short writeup:

```text
Finding:
Evidence:
Actor:
Time window:
Why it matters:
Impact:
Remediation:
Follow-up monitoring:
Confidence:
```

## Completion Checklist

- Events reviewed by time range.
- High-risk events identified.
- Failed or denied activity reviewed.
- Risky successful changes matched to remediation.
- Report generated by the Python analyzer.
- Manual analyst notes added where needed.
- Public copy sanitized.
